# GAS版 フクタハウス様への譲渡手順

**GAS版をフクタハウス様に譲渡することが決定**しました。本書はその具体的な操作手順です。

Supabase 版の譲渡計画（`docs/HANDOFF_PLAN.md` / `docs/SETUP_FUKUTA.md`）は**この決定により保留**です。GitHub / Cloudflare / Supabase の移管は不要になりました。

---

## 0. 前提と全体像

### 譲渡するもの

GAS版の実体は **Google ドライブ上のスプレッドシート1個だけ**です。スクリプト（`Code.gs` / `index.html`）はそのスプレッドシートに内蔵（コンテナバインド）されているため、**スプレッドシートを渡せばアプリごと渡ったことになります**。

```
スプレッドシート「フクタハウス 施工物件マップ DB」   ← これ1個が全て
├── 各シート（物件 / 点検履歴 / 各種マスタ / 設定）＝ データベース
└── 内蔵 Apps Script（Code.gs + index.html）        ＝ アプリ本体
```

### 譲渡後に必要になるもの（フクタハウス様側）

| # | 項目 | 備考 |
|---|---|---|
| 1 | Google アカウント（管理者用） | Workspace 推奨。個人 Gmail でも可 |
| 2 | Google Cloud プロジェクト + Maps API キー + Map ID | 地図表示用。中原さんのキーを使い続けない |
| 3 | 利用者の Google アカウント（個人 Gmail 可） | スプレッドシートを共有して利用許可にする |

**Supabase・GitHub・Cloudflare はいずれも不要です。**

### 認証のしくみ（スプレッドシート共有方式）

アプリは **利用者本人の Google アカウントの権限** で動きます（デプロイ設定「次のユーザーとして実行：ウェブアプリにアクセスしているユーザー」）。

- **スプレッドシートを共有された人だけ**が使えます。利用者の追加・停止は「共有」の画面で行います
- **URL は全員共通の1つ**（`.../exec`）です。利用者ごとのURLはありません
- 編集者で共有すると登録・編集もでき、閲覧者で共有すると見るだけになります
- 各利用者は初回だけ権限の承認画面を通ります

> **以前の方式から変えた理由**
> 「実行ユーザー＝自分」で動かすと、Workspace 外（個人 Gmail）の利用者のメールアドレスが取得できず、メールでの許可が成立しませんでした。その回避策だったトークン付きURL（1人1URL）は配布の手間が大きいため、現在の方式にしました。

### 現状（譲渡前）

- オーナー: 中原（BRANU）の Google アカウント
- 物件データ: 31件（Supabase 版から移行済み）
- 点検履歴: 0件
- 「設定」: 中原の Google Cloud で発行した API キー / Map ID

## 1. 譲渡方式の選択

Google では**アカウント間のオーナー権限移譲に制約**があります。状況に応じて方式を選びます。

| 方式 | 使える条件 | 長所 | 短所 |
|---|---|---|---|
| **A. オーナー権限を譲渡** | 相手が同一 Workspace 組織内、または双方が個人 Gmail | 履歴・URL がそのまま。最も綺麗 | **組織をまたぐと使えないことが多い** |
| **B. コピーを渡す**（推奨） | 常に可能 | 制約なし。確実 | ウェブアプリの URL が変わる／再デプロイが必要 |
| **C. 共有ドライブへ移動** | フクタ側が Workspace を持ち、こちらがそのメンバーになれる | 組織所有になり属人性が消える | 一時的にこちらがフクタ組織のアカウントを持つ必要がある |

> **迷ったら B（コピーを渡す）**。Google の制約に引っかからず、確実に完了できます。以下は B を前提に書きます。A や C が使える場合は「6. 方式A / C の場合」を参照してください。

## 2. 【中原さん作業】譲渡用コピーの準備

### 2-1. スプレッドシートを複製する

1. 現行スプレッドシートを開く
2. **ファイル → コピーを作成**
3. 名前を `フクタハウス 施工物件マップ DB（譲渡用）` などにする
4. 「コメントも共有する」等のチェックは不要

> ⚠️ **コピーすると内蔵スクリプトも一緒にコピーされます**が、**デプロイ設定はコピーされません**（後でフクタ側が再デプロイします）。

### 2-2. コピー側から自分の情報を消す

譲渡用コピーを開いて、以下を編集します。

**「設定」シート** — 中原の API キーを消す（フクタ側の値を後で入れてもらう）

| キー | 値 |
|---|---|
| `GOOGLE_MAPS_API_KEY` | **空にする** |
| `GOOGLE_MAPS_MAP_ID` | **空にする** |

**「ログイン許可」シート** — 現在の方式では使いません（残っていても影響なし）。利用許可はスプレッドシートの共有で決まります

### 2-3. 動作確認用データの整理

「物件シート貼り付け用」シートは作業用の控えです。譲渡用コピーでは**削除して構いません**（残しても害はありません）。

TEST 名義の物件データ（`TEST_〇〇`）が残っていれば、この時点で削除しておきます。

### 2-4. フクタ様に共有する

1. 譲渡用コピーの **共有** ボタン
2. フクタ様の管理者メールアドレスを **編集者** として追加
3. リンクをメール等で送付

## 3. 【フクタハウス様作業】受け取りと自社環境化

### 3-1. 自分のドライブにコピーする

共有されたスプレッドシートを開き、**ファイル → コピーを作成**。

これで**フクタハウス様がオーナーのスプレッドシート**が出来ます。以降はこのコピーを本番として使います。

> この一手間で「中原さんのドライブに依存しない」状態になります。共有されたままの元ファイルは使わないでください。

### 3-2. Google Cloud で地図用のキーを発行する

1. https://console.cloud.google.com を開く（会社の Google アカウントで）
2. **新しいプロジェクト**を作成（例: `fukuta-house-map`）
3. **お支払い** → 請求先アカウントを作成しクレジットカードを登録
   - 無料枠内で収まる見込みですが、Google の規約上カード登録は必須です
4. **APIとサービス → ライブラリ** で **Maps JavaScript API** を有効化
   - ※ Geocoding API は不要（GAS の内蔵機能を使うため）
5. **APIとサービス → 認証情報 → ＋認証情報を作成 → APIキー**
   - 発行された `AIza...` を控える
6. 検索バーに **Map Management** と入力して開く → **マップIDを作成**
   - 地図の種類: **JavaScript**、**Vector** を選択
   - 発行された Map ID を控える

### 3-3. API キーに利用制限をかける

発行した API キーの「編集」を開き、以下を設定します。

- **アプリケーションの制限**: ウェブサイト（HTTPリファラー）
  ```
  https://script.google.com/*
  https://*.googleusercontent.com/*
  ```
  ⚠️ **両方必要です。** GAS のウェブアプリは中身が `googleusercontent.com` の iframe で動くため、片方だけだと地図が表示されません。
- **APIの制限**: キーを制限 → **Maps JavaScript API** のみ選択

### 3-4. スプレッドシートに設定を入れる

コピーしたスプレッドシートの **「設定」シート**に、3-2 で控えた値を入力します。

| キー | 値 |
|---|---|
| `GOOGLE_MAPS_API_KEY` | `AIza...`（3-2 で発行したキー） |
| `GOOGLE_MAPS_MAP_ID` | 3-2 で発行した Map ID |

必要なら3行目に `OFFICE_ORIGIN` を追加し、「現地へ行く → フクタハウスから」の出発地を自社住所の緯度経度（例: `35.485869,136.897825`）に設定できます。

### 3-5. ウェブアプリとしてデプロイする

1. **拡張機能 → Apps Script** を開く
2. 右上の **デプロイ → 新しいデプロイ**
3. 歯車 → **ウェブアプリ** を選択
4. 設定:
   - **説明**: 任意（例: `初回デプロイ`）
   - **次のユーザーとして実行**: **ウェブアプリにアクセスしているユーザー**
   - **アクセスできるユーザー**: **Google アカウントを持つ全員**
5. **デプロイ** → 初回は権限承認を求められるので許可
   - 「このアプリは確認されていません」と出たら **詳細 → （プロジェクト名）に移動** で進む（自作アプリのため正常）
6. 表示された **ウェブアプリの URL**（`.../exec` で終わる）を控える

### 3-6. 利用者に共有し、URLを配る

1. スプレッドシート右上の **共有** から、利用者の Google アカウントを追加する
   - 登録・編集もする人：**編集者**
   - 見るだけの人：**閲覧者**
2. 3-5 で控えた URL（`.../exec`）を**全員に同じものを**配る
3. 各利用者は初回だけ承認画面が出ます。「このアプリは確認されていません」と出たら **詳細 → （プロジェクト名）に移動** で進んでもらいます

- 利用者を外すときは、共有から削除するだけです。再デプロイは不要です
- 編集者はシートやコードを直接開けるので、「シートは直接触らずアプリから操作する」よう周知してください

### 3-7. 動作確認

3-5 で控えた URL を開いて、以下を確認します。

- [ ] 地図が表示される
- [ ] 物件のピンが表示される（**ピンが出ない＝Map ID の設定漏れ**）
- [ ] 物件をクリックして詳細が出る
- [ ] 「物件追加」で1件登録できる → スプレッドシートの「物件」シートに行が増える
- [ ] 登録したテスト物件を削除できる
- [ ] 共有していない Google アカウントで開くと「利用権限がありません」になる
- [ ] 閲覧者で共有したアカウントでは、地図は見られて保存はできない
- [ ] スマホで開いて操作できる

## 4. 【中原さん作業】譲渡完了後の後片付け

フクタ様側の動作確認が済んでから実施します。

1. **フクタ様のスプレッドシート**の共有から、必要なくなれば中原を外してもらう
   - 保守で関わり続けるなら残す
2. **譲渡用コピー**（2-1 で作ったもの）を削除する
3. **現行スプレッドシート**は予備として一定期間（目安1ヶ月）残す
4. 中原の Google Cloud の API キーは、GitHub Pages 版を止めるタイミングで無効化する
   - Supabase 版をまだ動かすなら残す

## 4-2. 【既にデプロイ済みの場合】共有方式への更新手順

既にデプロイ済みの環境を、現在のコードに更新する手順です。**URL は変わりません**。

**コード編集者（中原さん・スプレッドシートの編集権限があれば可）**
1. スプレッドシート → **拡張機能 → Apps Script**
2. `コード.gs` の中身を、リポジトリの **`gas/Code.gs` の内容で全置換**して保存
3. `index` の中身を **`gas/index.html` の内容で全置換**して保存
4. 関数選択で **`setup`** を選び **実行**（電話番号列を文字列の書式にする。既存データはそのまま）
5. 動作確認したい場合は **デプロイ → デプロイをテスト** の `/dev` URL を開く

**利用者の共有（スプレッドシートの編集権限があれば誰でも可）**
6. スプレッドシートの **共有** に利用者全員を追加する（編集者／閲覧者）。**デプロイ前に済ませる**こと。共有されていない人は、デプロイした瞬間から開けなくなります

**デプロイした本人（フクタハウス様）** ← 他の人のデプロイは編集できないため、必ずデプロイした本人が行う
7. 同じ Apps Script エディタで **デプロイ → デプロイを管理**
8. 鉛筆アイコン → **次のユーザーとして実行** を **ウェブアプリにアクセスしているユーザー** に変更、**バージョン: 新バージョン** → **デプロイ**
   - 「アクセスできるユーザー」は **Google アカウントを持つ全員** のまま
   - 編集画面で「次のユーザーとして実行」が変更できない場合は、**新しいデプロイ**で作り直す（この場合だけ URL が変わるので、新しい URL を全員に配り直す）
9. 各利用者は次に開いたとき、初回だけ承認画面が出ます

## 5. 保守を続ける場合

譲渡後もこちらでコード修正を行うなら、フクタ様側で以下をしてもらいます。

- スプレッドシートの **共有 → 編集者**に中原のアドレスを追加

コードを直したときの反映手順は `gas/README.md` の「更新のしかた」を参照してください。**既存デプロイを編集して新バージョンを作る**のがポイントです（「新しいデプロイ」で作ると URL が変わり、社内に配ったリンクが切れます）。

## 6. 方式A / C の場合

### 方式A：オーナー権限を譲渡する

同一 Workspace 組織内、または双方が個人 Gmail のときだけ使えます。

1. 現行スプレッドシートを開く → **共有**
2. フクタ様の管理者を**編集者**として追加
3. 追加した相手の行の権限メニュー → **オーナー権限を譲渡**
4. 相手が承諾すると移管完了

この方式なら 3-1（コピー作成）は不要です。ただし**デプロイはオーナーが変わると作り直しが必要**なので、3-5 は実施してください。「設定」シートの API キー差し替え（3-2〜3-4）も同様に必要です。

> 組織をまたぐ場合、この選択肢がグレーアウトして選べません。その場合は方式B に切り替えてください。

### 方式C：フクタ様の共有ドライブに置く

フクタ様が Google Workspace を使っていて、こちらがそのメンバーアカウントを一時的にもらえる場合に使えます。

1. フクタ様の共有ドライブに招待してもらう
2. スプレッドシートを共有ドライブに**移動**する
3. 以降そのファイルは**組織所有**になり、個人アカウントに依存しなくなる

長期運用では最も安全な形です。担当者が退職してもファイルが消えません。

## 7. よくあるつまずき

| 症状 | 原因 | 対処 |
|---|---|---|
| 地図が真っ白 | API キー未設定 / リファラー制限の不備 | 「設定」シートと、リファラーに `googleusercontent.com` があるか確認 |
| 地図は出るがピンが出ない | **Map ID 未設定** | 「設定」シートの `GOOGLE_MAPS_MAP_ID` を確認 |
| 「利用権限がありません」 | そのアカウントにスプレッドシートが共有されていない | 共有に追加。複数アカウントでログインしている場合は、共有したアカウントに切り替える |
| 「あなたのアカウント: （取得できませんでした）」と出る | **旧版（メール認証）のコードが動いている** | 4-2 の手順で更新 |
| 保存すると権限エラー | 閲覧者で共有されている | 編集させるなら編集者に変更 |
| 「このアプリは確認されていません」 | 自作 GAS の通常挙動 | 「詳細」→「〇〇に移動」で進む |
| 「シート「物件」がありません」 | `setup()` 未実行 | Apps Script から `setup` を実行 |
| コードを直したのに変わらない | デプロイ未更新 | デプロイを管理 → 編集 → 新バージョン |
| 配ったURLが急に開けない | 「新しいデプロイ」で作り直した | 旧URLは無効。新URLを配り直すか、次回から既存デプロイを編集する |
