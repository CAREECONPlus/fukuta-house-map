# GAS版 — フクタハウス 施工物件マップ

Google スプレッドシートをデータベースにし、Google Apps Script（GAS）のウェブアプリとして動かす版です。Supabase 版（リポジトリ直下の `index.html` / `src/`）とは**別実装**で、機能は同等です。

このディレクトリのファイルは **Apps Script エディタ上のコードのバックアップ兼バージョン管理用**です。ここのファイルを直接編集してもアプリには反映されません（反映方法は下記「更新のしかた」を参照）。

---

## 構成

| ファイル | Apps Script 上の名前 | 役割 |
|---|---|---|
| `Code.gs` | `コード.gs`（スクリプトファイル） | サーバー側。シート読み書き・権限チェック・ジオコーディング |
| `index.html` | `index`（HTMLファイル） | 画面側。地図・一覧・フォーム・CSV入出力の全UI |

データ本体（スプレッドシート）と API キーはこのリポジトリには含みません。

---

## Supabase版との違い

| 項目 | Supabase版 | GAS版 |
|---|---|---|
| データベース | Supabase (PostgreSQL) | Google スプレッドシート |
| ホスティング | GitHub Pages | GAS ウェブアプリ |
| 認証 | なし（URLを知っていれば誰でも） | **スプレッドシートの共有**（共有された Google アカウントだけが使える。URLは全員共通） |
| ジオコーディング | Google Maps Geocoding API | GAS 内蔵 `Maps.newGeocoder()`（APIキー不要） |
| APIキーの持ち方 | GitHub Actions Secrets | スプレッドシートの「設定」シート |
| 費用 | Supabase 無料枠 | Google アカウントのみ（追加費用なし） |
| 停止リスク | 無料枠は1週間放置でPause | なし |

GAS版はジオコーディングに GAS 内蔵機能を使うため、**Google Maps の API キーは地図表示にしか使いません**。

## スプレッドシートの構成

`setup()` を実行すると以下のシートが自動生成されます。

| シート名 | 役割 |
|---|---|
| 物件 | 物件データ本体（16列） |
| 点検履歴 | 点検・アフターケアの記録 |
| 種別マスタ | ブランド（brand）と物件タイプ（building_type）を `区分` 列で区別 |
| カテゴリマスタ | 住宅・電柱・調整池・道路 ＋ 追加分 |
| 営業所マスタ | 電柱の「営業所」選択肢 |
| 設定 | `GOOGLE_MAPS_API_KEY` / `GOOGLE_MAPS_MAP_ID` / （任意）`OFFICE_ORIGIN` |

旧版で作られた「ログイン許可」シートと「設定」の `WEB_APP_URL` 行は使わなくなりました。残っていても動作に影響はありません（削除しても構いません）。

### 認証方式について

ウェブアプリを **「次のユーザーとして実行：ウェブアプリにアクセスしているユーザー」** でデプロイし、**利用者本人の Google アカウントの権限**でスプレッドシートを読み書きします。

- スプレッドシートを共有された人だけが使える（共有されていない人は「利用権限がありません」）
- **編集者**で共有 → 閲覧・登録・編集・削除ができる
- **閲覧者**で共有 → 地図と一覧は見られるが、保存・削除はエラーになる（閲覧専用の利用者に使える）
- URL は全員共通の `.../exec` 1つ。利用者ごとのURLやトークンはありません
- Google アカウント（個人 Gmail 可）が必須です

> 経緯：以前は「実行ユーザー＝自分」で動かし、メール照合やトークン付きURLで許可していました。前者は Workspace 外のアカウントでメールが取れず全員が弾かれ、後者は1人ずつURLを配る手間がかかるため、現在の方式に変更しました。

**注意**：編集者はスプレッドシートを直接開けるので、シートや Apps Script のコードも編集できてしまいます。利用者には「シートは直接触らず、アプリから操作する」よう周知してください。

### 「物件」シートの列順（変更禁止）

```
id / カテゴリ / 物件名 / 住所 / ブランド / 物件タイプ / 土地区分 /
施工完了年月 / 電話番号 / 緯度 / 経度 / 備考 / 表示 /
追加情報 / 作成日時 / 更新日時
```

`追加情報` はカテゴリ固有項目を JSON で持つ列です。例：

```json
{"pole_number":"A123","power_company":"中部電力","office":"関営業所","pole_count":"1","stay_wire":"無"}
{"area_m2":"462.73","manager":"住民"}
{"road_name":"市道101号","width_m":"4.0"}
```

## 新規に立ち上げる手順

1. Google スプレッドシートを新規作成する
2. メニュー **拡張機能 → Apps Script** を開く
3. 既定の `コード.gs` の中身を、このリポジトリの **`Code.gs` の内容で全置換**する
4. 左の **＋ → HTML** で `index` という名前のファイルを作り、**`index.html` の内容を貼り付ける**
   - ファイル名は必ず `index`（`Code.gs` 側が `createTemplateFromFile('index')` で参照しているため）
5. 関数選択で `setup` を選び **実行**。初回は権限承認を求められるので許可する
   - シートとマスタの初期値が自動生成される
6. スプレッドシートの **「設定」シート**に値を入れる
   - `GOOGLE_MAPS_API_KEY` … Google Cloud で発行した Maps JavaScript API のキー
   - `GOOGLE_MAPS_MAP_ID` … Map Management で発行した Map ID（**無いとピンが表示されません**）
7. Apps Script の **デプロイ → 新しいデプロイ → 種類「ウェブアプリ」**
   - **次のユーザーとして実行**: `ウェブアプリにアクセスしているユーザー`
   - **アクセスできるユーザー**: `Google アカウントを持つ全員`
8. スプレッドシートの **共有** で、利用者の Google アカウントを **編集者**（見るだけの人は閲覧者）として追加する
9. 発行された `.../exec` の URL を開いて動作確認し、**同じURLを全員に配る**
   - 各利用者は初回だけ権限の承認画面が出ます。「このアプリは確認されていません」と出たら **詳細 → （プロジェクト名）に移動** で進みます（自作アプリの通常の表示）

### Google Cloud 側の設定

- 有効化する API: **Maps JavaScript API**（地図表示）
  - ※ Geocoding API は GAS 内蔵ジオコーダを使うため**不要**
- API キーの **HTTP リファラー制限**に以下を追加する
  ```
  https://script.google.com/*
  https://*.googleusercontent.com/*
  ```
  GAS のウェブアプリは iframe 内が `googleusercontent.com` になるため、両方が必要です。

## 日常の運用

### 利用者を追加する
スプレッドシートの **共有** でその人の Google アカウントを編集者（または閲覧者）として追加し、共通のURLを渡す。アプリの再デプロイは不要です。

### 利用者を外す
スプレッドシートの共有からその人を削除する。次回アクセスから使えなくなります。

### URL が漏れたとき
URL を知っていても、共有されていないアカウントでは開けません。対応は不要です。

### 選択肢（ブランド・物件タイプ・カテゴリ・営業所）を増やす
アプリ画面内の「種別を管理」「カテゴリを管理」「営業所を管理」から追加・削除できます。シートを直接編集しても構いません。

### データを直接直す
スプレッドシートを直接編集して問題ありません。ただし **`id` 列と列の順番は変更しない**でください。

## 更新のしかた（コードを直すとき）

このリポジトリと Apps Script は自動連携していません。以下のどちらかで同期します。

**A. 手動コピー（少人数向け・簡単）**
1. リポジトリ側のファイルを編集して commit
2. Apps Script エディタに内容を貼り付け
3. **デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン「新バージョン」→ デプロイ**
   - ※「新しいデプロイ」で作ると **URL が変わってしまう**ので、既存デプロイの編集で更新すること

**B. clasp を使う（開発者向け）**
```bash
npm install -g @google/clasp
clasp login
clasp clone <スクリプトID>   # 既存プロジェクトに紐づけ
clasp push                   # ローカル → Apps Script へ反映
```
`clasp` を使う場合は `appsscript.json` も管理対象になります。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 「利用権限がありません」と出る | そのアカウントにスプレッドシートが共有されていない。共有に追加する。複数の Google アカウントでログインしている場合は、共有したアカウントに切り替える |
| 「URLに利用者トークン（?t=…）が付いていません」と出る | 旧版（トークン方式）のコードが動いている。デプロイの更新漏れ |
| 保存すると「権限がありません」系のエラー | その人が**閲覧者**で共有されている。編集させるなら編集者に変更 |
| 「Google ドライブへのアクセスをリクエスト」などの画面が出る | 「実行ユーザー」が自分のまま。デプロイの「次のユーザーとして実行」を確認 |
| 地図が真っ白 | API キー未設定、またはリファラー制限に `script.google.com` が無い |
| 地図は出るがピンが出ない | **Map ID が未設定**。「設定」シートの `GOOGLE_MAPS_MAP_ID` を確認 |
| 「シート「〇〇」がありません」 | `setup()` が未実行。Apps Script から実行する |
| 保存が失敗する・遅い | 同時編集のロック待ち。時間をおいて再試行 |
| 更新したのに反映されない | デプロイの更新漏れ。「デプロイを管理」から新バージョンを作る |
